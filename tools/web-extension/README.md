# Readeck 剪藏助手（中文增强版）

把**浏览器渲染之后**的页面保存到 Readeck。小红书的图片、知乎的懒加载图片、贴吧/站酷这类纯 JS 渲染的页面，服务端抓不到的内容这里都能拿到。

## 与原版扩展的区别

| | 官方扩展 | 本扩展 |
| --- | --- | --- |
| 界面 | 英文 | 中文 |
| 小红书 / 贴吧 / 站酷 | 部分站点注入失败 | 直接抓当前标签页的 DOM，与站点无关 |
| 图片 | 仅写回地址，服务端再下载 | 可内嵌成 `data:` URL（防盗链、需要登录也能存） |
| 懒加载 | 需手动滚动 | 自动滚动到底再抓（可关） |

## 安装（Chrome / Edge，免打包）

1. 打开 `chrome://extensions`（Edge 是 `edge://extensions`），右上角打开 **开发者模式**。
2. 点 **加载已解压的扩展程序**，选择本目录 `tools/web-extension`。
3. 点扩展图标，填两项设置：
   - **服务器地址**：例如 `https://myreadeck.example.com:15351`（不要带尾斜杠）
   - **API 令牌**：Readeck 右上角头像 → 设置 → **API 令牌** → 新建，复制生成的令牌
4. 点 **保存设置**。

## 使用

1. 打开要保存的页面，等它加载完（扩展默认会自己滚到底触发懒加载）。
2. 点扩展图标 → **保存到 Readeck**。
3. 弹窗显示 `已提交（<书签 ID>）` 即成功，几秒后刷新 Readeck 即可看到。

两个选项：

- **图片内嵌为 data URL**：最稳。图片先由扩展取回再写进 HTML，防盗链、`blob:`、需要登录的图片都能保存。体积大一些。
- **先滚动到底触发懒加载**：小红书、微博、知乎这类滚动才出图的页面建议保持开启。

## 小红书：只存这一篇笔记

小红书笔记页（`/explore/<id>`）本身是一条无限信息流：往下滚会陆续加载几十条**别的**笔记。
如果像普通网页那样整页克隆，归档里就会混进作者的点赞收藏数、「说点什么…」输入框，
以及一堆推荐笔记的封面（实测一篇 8 图的笔记，整页克隆出来 41 张图，多出来的 33 张全是
推荐封面，尺寸 640×853，与正文的 1080×1920 完全不同）。

所以小红书走单独的抓取路径：

1. 从 `window.__INITIAL_STATE__.note.noteDetailMap[<当前笔记 id>].note` 里取标题、
   正文、作者、时间、IP 属地、`imageList`（含每张图的宽高）和视频。
2. 在页面里拼一个干净的 `<article>`：`<h1>` + 一行作者/时间元信息 + 正文段落 +
   每张图一个 `<figure><img>`，**不滚动、不克隆整页**。
3. 万一 state 结构变了，退回按 `#noteContainer` 范围抓取（只取笔记容器内的图，
   排除头像、图标和容器外的推荐封面）。

这样归档结果与「粘贴链接让服务端解析」一致：8 张图就是 8 张图。

## 动图（GIF）为什么会变成静态图

有些站点（B 站动态、部分图床）在检测到浏览器支持 WebP 后，会把图片地址重写成
`xxx.gif@880w_880h.webp`。CDN 对 `.webp` 请求返回的是**单帧静态图**，所以归档里
就成了静止画面。

扩展会把这个后缀去掉，还原成 `xxx.gif@880w_880h` 再提交，服务端拿到的就是原始
动态 GIF。如果你改过脚本，注意保留这段 `restoreOriginal` 逻辑。

## 抓取方式

普通站点把 `document.documentElement` 克隆一份，解析 `data-src` / `file` / `zoomfile` 等懒加载属性，可选内联图片，然后 `POST /api/bookmarks`，带上 `{url, title, html}`。Readeck 的 API 原生支持直接提交 HTML，因此不触发服务端抓取，也就不存在"服务端看不到 JS 内容"的问题。

小红书例外：见上一节，用页面内嵌的 state 重建正文，避免把整条信息流一起存下来。

## 更新

改过代码后，在 `chrome://extensions` 里点本扩展卡片上的 **重新加载**（↻）即可，
不需要重新添加。当前版本 **1.1.0**。

## 权限说明

- `activeTab`、`scripting`：仅在点击扩展时注入抓取脚本。
- `storage`：保存服务器地址与令牌（只存在本机浏览器里）。
- `<all_urls>`：需要读取任意站点的图片（含 CDN），并允许把内容提交到你自己的服务器。
